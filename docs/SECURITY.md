# Security boundary — V1.7

Threat model: a hostile anonymous browser, an authenticated low-privilege account, credential stuffing, CSRF, session theft, OTP replay, malicious request headers and public access to administrative endpoints. Host/root or database-admin compromise is outside the protection offered by this application. No claim of certification or penetration testing.

- Django is the authorization authority. Next.js receives no database secrets. Workspace UI is not an authorization boundary. All accounts require a role profile and a verified password plus TOTP. No default admin, no public registration, no password-only fallback, no browser JWT storage. Client accounts cannot read inquiries or staff audit data; future project/organization object-level checks are not implemented in this release.
- Server-side database sessions, fresh session at login, rotated CSRF token, host-only Secure/HttpOnly/Lax cookies in production; 30-minute inactivity timeout (activity saved at most once a minute), eight-hour absolute limit. Password reset, role changes and operator revocation invalidate existing sessions on their next request; requests already in flight cannot be recalled. All password changes require current password and a new TOTP.
- TOTP uses PyOTP, encrypted at rest with Fernet and a separate secret. Row lock prevents reuse of an accepted time step. TOTP is not phishing-resistant; WebAuthn/passkeys are future work. Use a synced clock. Keep the MFA key backed up separately from the database; loss requires verified operator re-enrollment. Provisioning displays a seed only in a trusted non-recorded terminal. No emailed recovery or backup codes yet; verify identity out of band before operator reset. Never paste seeds into tickets or chat.
- Argon2id is the default password hasher, minimum 15 characters, 256 maximum, common and numeric password checks. Generic login error; no public user lookup. Legacy hash timing may vary, and this is not a formal side-channel proof. Rotate legacy credentials through the operator command.
- PostgreSQL fixed-window attempt reservations coordinate all workers (global 180, IP 30, account 20, account/IP 5 per five minutes, per scope). Gateway has separate IP rate limits. Fixed windows permit boundary bursts; shared NATs and deliberately targeted usernames may be temporarily throttled. No bot challenge yet. Schedule daily security_cleanup and monitor saturation; scale rate limiting only after load tests.
- Every auth POST requires same-origin JSON plus Django CSRF (including anonymous login). CSRF token is obtained through GET and used in memory, never stored in localStorage. No CORS wildcard; no cross-origin client support. Public inquiry remains anonymous, origin checked, bounded and limited, with no session authority. Origin is not proof of a real human; production public inquiry may need CAPTCHA/WAF.
- Default DRF permissions deny access; public inquiry explicitly opts into AllowAny. Auth endpoints are plain Django JSON views to apply CSRF even before authentication. Unmounted legacy Django admin and schema routes cannot bypass MFA. API contract for auth is in auth.openapi.yaml; existing inquiry schema remains generated separately.
- Nonce-based CSP on HTML routes in Next.js; no unsafe-inline scripts in production. Inline styles and Google Fonts are allowed for current design. This intentionally makes pages dynamic rather than static, including Blog; metadata/SEO remains. Verify browser hydration and CSP in production. Dev permits unsafe-eval/HMR. Third-party script additions require review. Security headers and HTTPS are configured; no CORS allowance. HSTS excludes subdomains until deployment review.
- Production compose isolates database and API networks. PostgreSQL runtime role has DML but not ownership/DDL; after migration it cannot update/delete security audit records or mutate migration history. This is not tamper-proof: a DB administrator can alter logs and a compromised runtime can insert false events. Export security events to an independent append-only sink before high-risk production usage.
- Nginx overwrites client IP and HTTPS headers; trust them only when backend is private to this edge. If adding Cloudflare, configure trusted real-IP ranges and prevent direct origin access first; do not blindly trust CF headers. Database TLS disabled in the local single-host internal network example; for remote DB require verified TLS (sslmode=verify-full, trusted CA). No published DB/backend ports in production compose.
- Audit records store action, timestamp, actor ID and optional keyed identity fingerprint, not passwords, OTP, cookies or raw request bodies. Treat logs as sensitive. Set retention per policy, use external backups, alert on login failures/429/5xx. Do not enable body logging or debug in production.

Release gates: install dependencies from a verified registry and lock exact versions; run dependency/image vulnerability scans and patch findings. Run Django tests against PostgreSQL, migration check, `check --deploy`, Next production build, real-browser E2E including CSP, cross-origin/role bypass attempts, concurrent OTP replay and rate limiting, database grants, certificate renewal, restart/backup restore, and external security review. None are replaced by syntax checks. TLS certs, hostname, secrets and external monitoring are operator-owned configuration.
