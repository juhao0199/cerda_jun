# V1.9.2.1 — Editorial workspace

Incremental frontend update against V1.9.2 (including the V1.9.1 cover-upload update). No backend, database, dependency or lockfile changes. Existing `document` JSON, legacy sections and publication permissions remain unchanged.

- Full-screen mode covers the whole editor, including save, preview, publishing and settings. The editor is not remounted when entering full screen or preview. Full screen makes underlying workspace chrome inert and limits Tab navigation to the visible editor controls.
- Grouped SVG formatting controls, heading selector, desktop contextual selection toolbar, selected-image and table actions. On small screens use the persistent toolbar instead of the floating toolbar.
- Split writing canvas and article settings with responsive layout; title, summary and cover preview in the canvas. Metadata, publishing and history in settings.
- Persistent save status; Ctrl/Cmd+S to save a draft, not publish. Existing five-second autosave and conflict handling retained. Publish still requires an Owner, a saved current revision and explicit confirmation. No publication from historical preview.
- Beforeunload and explicit Workspace navigation/sign-out guards for unsaved work. Browser history traversal, session expiry or a crashed tab cannot guarantee unsaved content recovery. No browser-local copies of private articles are stored.
- Link and image alt/caption editing still use existing native prompts. No new image resizing, Media Library, advanced SEO scoring or storage migration in this patch.

## Apply

From the project root, while on the V1.9.2 development branch (or a new branch based on merged V1.9.2):

```sh
git apply --check ~/Downloads/cedar-v1.9.2.1-editor-experience.patch
git apply ~/Downloads/cedar-v1.9.2.1-editor-experience.patch
npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build
npm --prefix frontend run test:e2e -- blog.spec.ts --workers=1
```

Stop the existing Next.js dev server before the production build and E2E tests. Start with `npm --prefix frontend run dev`. No Docker rebuild, npm install, or database migration is required if V1.9.2 is already installed. Do not force-apply a conflicting patch.
