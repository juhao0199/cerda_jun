# V1.8.5 Complete CRM

Increment on V1.8.4 (including the preceding E2E and Team label hotfixes). Back up the database before applying. No dependency changes.

## Install from project root

```sh
mkdir -p backups
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backups/pre-v185.dump
docker compose exec -T db pg_restore -l < backups/pre-v185.dump
git apply --check ~/Downloads/cedar-v1.8.5-complete-crm.patch
git apply ~/Downloads/cedar-v1.8.5-complete-crm.patch
docker compose up -d --build backend
docker compose exec backend python manage.py makemigrations --check --dry-run
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py check
```

Stop any existing frontend server, then `npm --prefix frontend run dev`. Open `/workspace/leads`. Owner can add new leads even if there are no website inquiries. Staff can edit their active assigned leads; only Owner can create, archive/restore, and change unconverted email. Archive hides the lead from active views and removes Staff access, retaining the assignee for restoration. Owner still sees existing client records. CSV export is scoped, audited, requires CSRF, excludes notes and briefs, and rejects exports above 2,000 rows. CSV download includes personal data; store it securely. Duplicate detection is an exact normalized email warning, not an enforced uniqueness guarantee or fuzzy match. Website original data and pricing estimate are retained, distinct from CRM overrides. Amounts are estimates, not quotes or converted FX totals. Tags are editable comma-separated labels. No hard deletes.

## Verification

```sh
docker compose exec backend python manage.py test apps.accounts apps.inquiries --verbosity=2
npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build
npm --prefix frontend run test:e2e -- complete-crm.spec.ts --workers=1
```

Also run previous `pipeline.spec.ts`, `assignment.spec.ts` and `team.spec.ts`. E2E uses mock API responses and doesn't prove backend authorization. The current build environment can run Node domain tests and syntax checks but lacks project dependencies, Django and PostgreSQL. Full build, migration and E2E require local testing. Production deployment requires the updated Nginx config and normal migration process; run `nginx -t` in the deployed environment. Do not reverse migrations casually: removing new columns would lose CRM data. Keep backup files private.
