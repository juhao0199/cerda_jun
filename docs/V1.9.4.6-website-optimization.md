# V1.9.4.6 — Website-wide Content Optimization

Requires V1.9.4.5.14 (including the three networking hotfixes). No new npm/Python dependencies.

## Scope
- `/workspace/website` manages homepage and blog index title, description, noindex, canonical (derived from SITE_URL), Open Graph and Twitter metadata. Anchored homepage sections are not separate indexable routes. Article settings remain in Blog CMS; privacy copy and its noindex remain source-managed. Sitemap includes the actual indexable routes and articles only; privacy is excluded.
- Editable homepage headings/introductory copy in 12 groups, and FAQ / project guidance question-answer pairs. Existing UI, motion, demo data, hero headline, navigation and business logic are not CMS fields. Default text matches source. Limits keep headings short but final copy still requires responsive visual review.
- Organization/WebSite/WebPage graph, optional Service and FAQPage entities from the same visible content. No freeform JSON-LD/HTML or fabricated credentials, ratings or rankings. Search previews are illustrative; structured data is not a promise of search or AI inclusion. Domain preview in workspace uses planned production domain; server output uses SITE_URL.
- Staff and Owner can save a versioned draft. Owner publishes saved draft or restores a revision to draft. Public API returns only published values (or original defaults on initial seed); private keyword/history never included. Concurrency conflicts return 409; source defaults can be loaded as a new draft. Revisions retain snapshots and actor IDs, audit uses existing auth security log.
- Competitor topic coverage reads published homepage copy/FAQ only, not draft; not a complete DOM crawl and not a comparable SEO score.
- Read failure uses original homepage copy and conservative noindex; sitemap errors rather than falsely reporting successful published inventory. No public browser rewrite for the direct server-to-server public website endpoint.

## Local deployment
Back up PostgreSQL, create a branch from tested v1.9.4.5.14, apply patch, rebuild backend and run makemigrations --check --dry-run, migrate, check. Production must re-run existing runtime-grants.sql as migrator after migration and deploy revised Nginx allowlist. Confirm SITE_URL matches canonical public origin.

## Verification
Python unit rules, frontend node tests, Python/TS syntax, default parity, forward/reverse patch checks can run independently. Django integration tests and mocked Playwright UI tests require actual application dependencies. Run both, then perform manual published source/metadata check and restore the original values before publishing production content. `NEXT_PUBLIC_INQUIRY_MODE=local` for full browser regression; production build uses live mode. Do not test edits on production.
