# V1.8.3 — Team & access / Security center

Incremental upgrade from V1.8.2 including the E2E hotfix. No new dependencies. The public website, pricing, login, session middleware and existing CRM remain unchanged. The legacy security-events endpoint is retained for compatibility.

## Upgrade (from repository root)

1. Back up the current code and database (including MFA encrypted data); protect backups and keep the existing encryption key. Stop the development frontend before rebuilding.
2. `git apply --check /path/to/cedar-v1.8.3-team-security.patch` then `git apply /path/to/cedar-v1.8.3-team-security.patch`.
3. `docker compose up -d --build backend`
4. `docker compose exec backend python manage.py makemigrations --check --dry-run`
5. `docker compose exec backend python manage.py migrate`
6. `docker compose exec backend python manage.py check`
7. `docker compose exec backend python manage.py test apps.accounts apps.inquiries --verbosity=2`
8. `npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build`
9. `cd frontend && npm run test:e2e -- team.spec.ts --workers=1`
10. `npm run dev`, visit `/workspace/team` and `/workspace/security`.

The only migration adds a nullable indexed target account identifier to SecurityEvent; existing records retain a null target. In production, run migrations using the separate migrator role and deploy/reload the updated Nginx config. Do not run migration as the restricted runtime role. Existing runtime grants apply to the same audit table; verify INSERT and SELECT work while UPDATE/DELETE remain denied. See the existing production/security documents.

## Account lifecycle

Create a staff account from a private interactive terminal: `docker compose exec backend python manage.py provision_account staff01 --role staff`. Have the intended account holder enroll the authenticator in a trusted, private ceremony; never send the seed or password via chat/email or store it in tickets or logs. Wait for a new code before login. Account reset and Owner lifecycle remain operator-only. No public registration, credential recovery UI, or invitations in this release.

Only Owner can list or manage accounts and read the new audit endpoint. Changes to non-owner accounts require the Owner's current password and an unused TOTP. The existing shared throttle applies to a separate team scope. Every successful action increments the target's session version, invalidating previous sessions at their next request; already-running requests are not cancelled. Owner, Django staff and superuser targets are protected. No account deletion. Do not interpret Staff as Django `is_staff`. Lead assignment and per-record staff restrictions are not introduced; staff continue to share CRM data. No listing of individual live sessions or real-time alerts.

## API

Browser-facing paths are slashless; Django endpoints have a trailing slash. Existing Next rewrites and Nginx gateway route only the explicit paths. All responses inherit no-store security middleware.

- GET `/api/v1/staff/team`: `page` (1–1000), `search` (up to 150 chars), `role` (owner/staff/client), `status` (active/disabled). Returns `{results,page,hasMore}`, 30 records per page. Each record includes `id`, `username`, `role`, `active`, `version`, `lastLogin`, `protected`.
- POST `/api/v1/staff/team/action`: requires same-origin, CSRF and Owner session. JSON fields `id`, `version`, `action` (`revoke`, `disable`, `enable`, `role`), `password`, `code`, and only for `role`, `role` (`staff`, `client`). IDs and versions are decimal strings to avoid loss of precision. Returns updated account. 400 invalid input, 401 missing/revoked auth, 403 denied/verification failed, 404 missing account, 409 stale version, 429 throttled. Never retry a mutation automatically after ambiguous network failure. Reload and re-verify state. Password and OTP are not logged by this application; configure external reverse proxies, APM and error capture to avoid recording request bodies. Do not enable DEBUG in production.
- GET `/api/v1/staff/security-center`: `page`, `category` (login/logout/password/account/team/crm), `account` (numeric actor or target ID). Returns paginated audit events with string IDs and ISO timestamps; UI shows local time. Existing pre-upgrade events don't have target IDs. Audit remains read-only at the API.

Example step-up operation (illustrative placeholders, no real credentials):

```json
{"id":"2","version":"1","action":"revoke","password":"<current owner password>","code":"<fresh OTP>"}
```

## Verification

Seven new Django tests cover authorization, query validation, mass assignment, Owner protection, CSRF/origin, revocation, replay, stale version, account lifecycle, audit and pagination. Two browser tests (desktop and mobile) use mocked APIs; the browser tests do not prove database security. Full Django/PostgreSQL, Next.js typecheck/build, Playwright, production TLS and runtime-role checks must be run in the target environment. No independent security audit or live penetration test has been performed.
