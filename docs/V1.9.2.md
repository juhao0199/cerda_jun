# V1.9.2 — Advanced Rich Text Editor

Base: V1.9.1 Blog CMS plus Cover Upload. This patch updates the editor, article rendering and blog-only request limits, with no database schema changes.

## Install (project root)

1. Confirm `git status` is clean and the V1.9.1 cover-upload update is installed. Start a development branch from main if not already created: `git switch -c feature/v1.9.2-rich-editor`.
2. Back up PostgreSQL before editing articles with the new format. `mkdir -p backups; docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backups/pre-v192.dump`. Check `docker compose exec -T db pg_restore -l < backups/pre-v192.dump` succeeds. Keep backups private.
3. `git apply --check ~/Downloads/cedar-v1.9.2-rich-editor.patch` then `git apply ~/Downloads/cedar-v1.9.2-rich-editor.patch`.
4. `npm --prefix frontend install` (Tiptap 3 packages are new; review and commit the generated package-lock.json). No new Python dependencies.
5. `docker compose up -d --build backend` then `docker compose exec backend python manage.py makemigrations --check --dry-run` and `docker compose exec backend python manage.py check`. No new migration is expected.
6. Stop the existing Next.js process, `npm --prefix frontend run dev`, open `/workspace/blog`.

## Editor and publishing

- Rich editor: headings H2–H6, paragraph, bold, italic, underline, strike, inline code, HTTP(S)/local links, bullet/numbered lists, quotes, code blocks, divider, basic tables, undo/redo, fullscreen and a small slash menu on empty paragraphs. No H1 in body. Tables use equal-width unmerged cells (max 30 rows/10 columns); no syntax highlighting, galleries, checklist, CTA blocks or full drag-and-drop editor yet.
- Inline image insertion reuses secure cover upload. Alt text required; optional caption. Image is placed after the current top-level block; select it and edit alt/caption or delete using the editor. Images can be reordered at top level. External URLs and arbitrary HTML are not supported. The existing shared upload rate limit still applies. The same uploaded image is public only if referenced by a currently published cover or top-level body image. Existing private image history is retained.
- Existing `sections` and old revisions remain readable. Editing article body converts sections to a rich `document` JSON object; saving does not overwrite the published snapshot until Owner publishes. Text limited to 80,000 UTF-8 bytes, up to 4,000 nodes, depth 16, 30 distinct body images and 256 KiB total JSON. Only blog create/change request budgets are raised; existing authentication and CRM limits unchanged.
- Autosave after five seconds of inactivity for existing saved articles (first draft must be manually created). Autosave uses the same version-checked save API; failures pause it until a successful manual save/reload. The form temporarily locks during a request. No automatic publication. Browser close/reload warning and Back to articles confirmation remain; save before navigating elsewhere in the workspace. Undo history is local to the mounted editor, not durable across preview or reopening.
- Code rollback alone to V1.9.1 cannot display newly saved rich body documents; preserve the database backup and do not publish rich articles before acceptance. Old data and historical snapshots are not rewritten by a migration.
- Production: deploy the updated Nginx config alongside backend/frontend. No CSP relaxation or changes to DB grants are needed. Large media storage migration is a separate release.

## Acceptance tests

```
docker compose exec backend python manage.py test apps.accounts apps.inquiries apps.quotations apps.blog --verbosity=2
npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build
npm --prefix frontend run test:e2e -- blog.spec.ts --workers=1
```

Manually test formatting, a multi-row table, a code block, image upload and deletion, private preview, save, five-second autosave, version conflict in two tabs, Owner publish, anonymous public article and private image visibility, old article/revision rendering, archive/restore and mobile editing. Five E2E cases run on desktop and mobile; the new browser tests are mocked API tests, while Django tests exercise real persistence/permissions. Full browser and PostgreSQL tests are pending on the target Mac.
