# Content Operations Center — v1.9.5.1
Requires v1.9.5, including migration 0012. New migration 0013. No dependencies.

`/workspace/content`: create/edit/archive planning tasks, filter and paginate; drag between planning lanes or reschedule deadline by dragging onto a calendar date (accessible stage/date fields are also available). List, board and monthly deadline calendar show the current page of up to 100 matching tasks. Deadlines are date-only, not release times; actual release calendar remains `/workspace/calendar`. Published and scheduled lanes are derived from current article and publishing plan state. Changing a planning stage does not publish anything. Staff/Owner share marketing planning; assignees are active internal accounts, not access-control boundaries.

Topic clusters support primary/supporting keywords, market, intent, notes and archive. Import an existing open/in-progress competitor content opportunity once, retaining its source link. Link an existing article or create a private starter draft; private brief/outline are never copied into public article content. Starter text must be replaced before submitting or publishing. Source-linked tasks follow the opportunity's existing article. Article editing/publishing remains in Blog CMS and Editorial Calendar.

Content health compares up to 200 published article snapshots plus homepage/blog metadata for duplicate title, description, focus keyword and age >=180 days. No search volumes, search rankings or performance invented. This is a limited metadata review, not a complete DOM crawl. No bulk actions, weekly calendar, internal-link graph, automated keyword discovery or publishing automation changes in this increment.

Protected POSTs use existing CSRF/origin/role guards; version conflicts return 409. Task/cluster changes audited; no hard deletion. Apply migration and updated runtime grants + nginx config in production. Test independently with `python manage.py test apps.blog.test_operations apps.blog.test_operations_rules`, frontend unit tests and `npm run test:e2e -- content-operations.spec.ts --workers=1`.
