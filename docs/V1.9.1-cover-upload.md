# V1.9.1 cover upload increment

Apply on top of V1.9.1 Blog CMS. Rebuild backend, run migrations, restart frontend. The only new dependency is Pillow. The public article, listing thumbnails and metadata use the public cover API; editor and historical previews use staff-only API. Presets remain usable.

Upload is a raw image POST (5 MiB maximum) protected by session, CSRF, Origin, role checks, database-backed upload rate limiting and Nginx request size restriction. JPEG/PNG/WebP static input, at most 16 million pixels, re-encoded to metadata-free JPEG with maximum edge 1600 px. Transparent areas become white. The global JSON limit is unchanged.

New immutable `blog_coverimage` table stores processed bytes in PostgreSQL, so standard database backups cover images. Production runtime grants must be reapplied after migration, and Nginx updated. Only currently published snapshots grant public image access; if shared by another published article, an image remains public. Do not use a public image to store confidential data. Previously downloaded copies cannot be revoked. Unsaved/unreferenced images and historical images remain stored; there is no garbage collection or media library yet. Monitor storage and backups; consider object storage at larger scale. No change to existing article URLs or content.

Test: `docker compose exec backend python manage.py test apps.blog --verbosity=2`, `npm --prefix frontend test`, `npm --prefix frontend run typecheck`, `npm --prefix frontend run build`, `npm --prefix frontend run test:e2e -- blog.spec.ts --workers=1`.
