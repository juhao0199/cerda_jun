# V1.9.4.4 — AI Prompt Tracking & Citation Monitoring

**Baseline:** v1.9.4.3 Technical Audit. This replaces the abandoned Search Console integration proposal, not a continuation of its code. Both proposals use migration number 0008; do not install both. If `0008_search_snapshot` has been applied, stop and assess that migration before changing schema. Never delete a migration record or reset a database to force installation.

## Scope

`/workspace/monitoring` is a separate internal workspace, linked from AEO and GEO. No API keys, outbound network requests, scraping, Google Search Console or Bing Webmaster integrations. No automatic queries or notifications. Retest due dates are calculated on demand from the latest observed timestamp for each tracked engine. Historical generic `DiscoveryObservation` records remain intact and are not counted as structured citations.

- Prompt library: fixed question, language, market, intent, selected engines, 7/14/30-day cadence. Normalized duplicate protection; archive/restore with optimistic version check, no hard deletion. Context is immutable; use a new definition for a different question, market, language or engine set.
- Manual observations: copy question, perform a real search, record engine, time (stored UTC), model/interface/region/session context, answer relevance, brand presence, site citation, short evidence excerpt and up to eight reported HTTPS URLs. Exact domain match for cedarandcursor.com / www.cedarandcursor.com. URLs are rendered as text, never fetched or verified; use actual visible source URLs and do not store sensitive data. Positive citation requires an owned-domain URL. UUID retry token prevents duplicate submission of the same measurement; it cannot be reused for changed content.
- Dashboard: all recorded checks over the last 30 days; per-prompt history with 30/90/all and engine filter; top 20 reported site URLs among positive citation observations, counted once per check per exact URL. No URL canonicalization beyond owned-host detection. No data = no conclusion. Rates are found / (found + not found) for each dimension, excluding inconclusive. A relevant answer does not imply the studio was recommended. These are sample rates, not population estimates or rankings.
- Owner/staff can create prompts and append observations; owner alone archives/restores. Clients denied. Existing session/MFA, Origin/CSRF, transaction role recheck, audit log, bounded input and pagination. Production DB grants prevent deleting prompts and editing/deleting observation rows. PostgreSQL JSONB aggregation is used for the citation report.

## Upgrade

From clean v1.9.4.3 main, create `feature/v1.9.4.4-ai-monitoring`. Back up PostgreSQL using pg_dump and verify pg_restore -l. Apply `cedar-v1.9.4.4-ai-monitoring.patch` with git apply --check first. Rebuild backend, check pending schema changes, migrate and run system check. Start frontend normally; no npm/Python dependencies added. Production deploy must use updated Nginx allowlist and runtime-grants SQL.

```
docker compose up -d --build backend
docker compose exec backend python manage.py makemigrations --check --dry-run
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py check
npm --prefix frontend run dev
```
