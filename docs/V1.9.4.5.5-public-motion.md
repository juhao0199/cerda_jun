# V1.9.4.5.5 — Continuous product motion

Requires the V1.9.4.5.4 public-motion patch. Only the additive public studio chapters are changed; original home components, hero, global styles, backend, and workspace remain unchanged. No added dependencies.

- Operations: keyed, stable grid cards are moved using measured FLIP positions and Web Animations transform transitions. No automatic list/board swapping; manual search and moves still work. Positions are relative to the board, not the viewport. Cards use sample records.
- Web: persistent browser and three layered pages with inert hidden panels, fixed-height stage, responsive container layout and animated device width. Width/container changes still involve layout, so measure on target hardware.
- Knowledge: staged retrieval, response and source expansion, with persistent progress indicators. Prepared examples only.
- Automation: continuous progress spine with active node feedback. Human approval remains manual; never simulates approval as an automated result.
- Editorial composition: larger individual AI and automation sections, restrained monochrome surfaces, finer hierarchy and interaction feedback.
- Existing viewport, document visibility, manual pause and reduced-motion behavior retained. Decorative CSS animations are disabled under reduced motion. No frame-by-frame React state loop.

Run `npm --prefix frontend test`, `npm --prefix frontend run typecheck`, `npm --prefix frontend run build`, then `npm --prefix frontend run test:e2e -- site.spec.ts --workers=1`. Check desktop/mobile visually, including 60 Hz scroll, CPU throttling, card travel, responsive resize and manual control. Actual frame rate depends on hardware and browser; no guaranteed 60 fps claim.

The board now uses eight explicitly illustrative projects; the existing manual move assertion has been updated to expect two complete out of eight after completing Website refresh. A static markup/CSS fixture was inspected in Chromium at 1440 and 390 pixels (no horizontal document overflow; stable web-stage height during the device resize). This fixture is not a full React/Next.js runtime test.
