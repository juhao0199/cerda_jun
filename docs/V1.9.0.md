# V1.9.0 — Quotation Builder

Apply the patch from the repository root, on the V1.8.5 feature branch. Back up PostgreSQL first. Do not reset the database or delete Docker volumes.

```sh
cd ~/Downloads/cedar-cursor-v1.7
git status
# If not already on this branch:
git switch -c feature/v1.9.0-quotations
git apply --check ~/Downloads/cedar-v1.9.0-quotations.patch
git apply ~/Downloads/cedar-v1.9.0-quotations.patch
docker compose up -d --build backend
docker compose exec backend python manage.py makemigrations --check --dry-run
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py check
docker compose exec backend python manage.py test apps.accounts apps.inquiries apps.quotations --verbosity=2
npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build
npm --prefix frontend run test:e2e -- quotation.spec.ts --workers=1
```

The Docker rebuild installs ReportLab. No new npm dependency. After stopping any running development frontend, run `npm --prefix frontend run dev`. Open `/workspace/quotations` or use the link in a lead detail drawer. Create a lead first if the CRM is empty.

## Scope and lifecycle

Owner sees all quotes; staff sees only quotes attached to their currently assigned, non-archived leads. Client accounts have no quotation access yet. Archived leads are read-only for Owner. Writes recheck the authenticated account and row-level scope under transaction locks. Revision numbers are checked on every edit/transition. Each revision stores a frozen recipient and financial snapshot; editing a CRM contact does not retroactively edit a quote. Duplicate creates a separate draft with current lead contact info, not a legal copy of an issued document. Issue locks a draft; revise starts a new draft under the same quote number; void is terminal. Issuing a quote does not send it, accept it, invoice it, or change the lead status. Old revision PDFs are historical documents; check current status before sharing. The UI shows the most recent 100 revisions; older ones remain stored. No deletion API.

## Money and catalog

Up to 12 line items, quantity and unit price as decimal strings, percentage discount and percentage tax. Round each line to two decimals (half up), then discount the subtotal, then calculate tax on the discounted amount. Django is authoritative; live frontend totals are estimates. Supported currencies: USD, THB, SGD, EUR, GBP, AUD, NZD, AED. No FX conversion, automatic tax rules, tax registration validation, or tax-inclusive pricing. Payment terms are free text, not payment schedules or automated collections. Catalog contains service templates with no invented rates; enter negotiated prices yourself. Quotation numbers use the full UUID for uniqueness, not sequential invoice numbering.

## PDF

Protected server-generated A4 PDF from saved revisions. Standard PDF fonts support Windows-1252/Latin text only; other characters yield HTTP 422 instead of corrupt output. The web form stores Unicode. Historical PDFs are rendered from saved data and may look different after future template changes. This release does not store PDF bytes, send emails, or offer a public/customer approval link. Draft, issued and void PDF labels distinguish lifecycle state of that revision.

## Production

Deploy updated nginx routing, TLS, private backend and production cookies; check the production PDF and role policies. No production audit is claimed. The sample PDF uses synthetic contact info.
