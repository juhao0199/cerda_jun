# V1.9.4.5.4 — Automatic studio motion

Apply after V1.9.4.5.3 Additive Public Expansion. No dependencies, migrations, or backend changes. All motion is scoped to the added studio chapters; original Hero, 3D, estimator, forms, and navigation are unchanged.

- A viewport-aware timer runs each sample only when at least 20% of its frame is visible, the browser tab is foregrounded, and the visitor has not paused it.
- Web preview rotates device and sample pages; operations moves illustrative projects and switches views; knowledge cycles prepared answers and their sample source; automation advances to the human approval gate and loops without approving. Actual approval still requires an explicit visitor click. No network or live data actions occur.
- Pointer, click and focus interaction with a preview pause its automatic state changes. Play/Pause controls are per preview; restarting resumes the sample sequence, which may replace edits to sample data. Nothing is persisted.
- Scroll entrances are progressive enhancement. Reduced motion prevents autoplay and visual motion; manual controls remain usable. No animation hides content before hydration. If IntersectionObserver is unavailable, autoplay stays off.
- CSS motion and preview canvas sizes are local. No animation dependency is added.

Verification on the project machine:

```sh
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
npm --prefix frontend run test:e2e -- site.spec.ts --workers=1
```

Manually review mobile and desktop at different viewport sizes. Browser visual quality and full Next.js build require local dependencies.
