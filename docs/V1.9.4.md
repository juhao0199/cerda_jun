# V1.9.4 — Editorial directory and SEO center

Apply on V1.9.3 including both E2E/UI hotfixes. No new npm or Python packages. PostgreSQL is required (editorial writes take a transaction-scoped advisory lock to serialize the slug namespace and term changes).

## Install from project root

1. On the clean `feature/v1.9.4-seo-center` branch based on V1.9.3, back up PostgreSQL and verify `pg_restore -l`.
2. `git apply --check ~/Downloads/cedar-v1.9.4-seo-center.patch` then `git apply ~/Downloads/cedar-v1.9.4-seo-center.patch`.
3. `docker compose up -d --build backend` and `docker compose exec backend python manage.py makemigrations --check --dry-run`.
4. `docker compose exec backend python manage.py migrate` (blog.0005_editorial_seo), then `docker compose exec backend python manage.py check`.
5. Restart Next.js; `npm --prefix frontend run dev`. Open `/workspace/editorial`, `/workspace/seo`, and `/workspace/blog`.
6. For production apply updated runtime grants as migrator after migration and reload the updated Nginx configuration. Do not use an unverified SITE_URL. Actual deployment testing is required.

## Design and limits

- EditorialTerm stores case-insensitive names with archive/restore and version checks. Existing category/tag display names remain in snapshots; newly entered categories/tags register automatically on article save (including Staff). Owner alone explicitly manages the directory. Existing assigned archived terms can remain; newly assigning them is rejected. Names are immutable; create a replacement rather than globally rewriting historical snapshots. Authors are public display names, not login accounts; blank means Cedar & Cursor. Owner creates author identities. Only publicly assigned names should be used.
- SEO checks run on actual draft content in the editor, with a paginated metadata-only inventory in SEO Center. Focus phrase stays private. Cover alt, author and noindex become public only when Owner publishes. The score is editorial guidance, not ranking data. No external keyword volume or Search Console integration. Canonical remains self-referential to the configured SITE_URL and current slug; no arbitrary canonical overrides. Noindex does not prevent public reading, and noindexed articles remain in public list/RSS but are omitted from sitemap.
- Owner changes a clean saved article's slug explicitly. Previous slugs are reserved permanently; aliases resolve directly to the current slug, only while the target is published. Next.js permanentRedirect normally produces HTTP 308 (streamed responses may use a client/meta redirect); verify deployed HTTP behavior before release. Former private draft slugs are also reserved and redirect only once target is public. The current slug remains editable only through the explicit rename action, and historical snapshots are not rewritten. A rename is an immediate public URL operation if published. No alias deletion/reuse, public taxonomy archive pages, author profiles with bios, or bulk editing in this release.
- First publication timestamp is recovered from retained publication/import revisions where available; current publication date is fallback. Last published modification is separate from private draft update. Archiving removes public content; original first publication timestamp is retained. Migration does not rewrite existing article snapshots or files.

## Verify

```bash
docker compose exec backend python manage.py test apps.accounts apps.inquiries apps.quotations apps.blog --verbosity=2
npm --prefix frontend test && npm --prefix frontend run typecheck && npm --prefix frontend run build
npm --prefix frontend run test:e2e -- blog.spec.ts media.spec.ts editorial.spec.ts --workers=1
```

Use a disposable article for real integration checks: create author and category, save draft with SEO settings, confirm anonymous article returns 404; publish and check author/meta/alt; change noindex in draft and verify public HTML/sitemap unchanged until publish. After publishing noindex, verify meta robots noindex and omission from sitemap. Rename a published article, request old URL using `curl -I http://localhost:3000/blog/OLD-SLUG`, confirm permanent redirect to new URL; rename again and test original alias, archive and confirm old and new URL return 404. Check first published date remains stable on republish. E2E mocks verify UI, not actual permissions or real HTTP redirects; use Django tests and live checks too.

Rollback requires caution: keep pre-upgrade DB backup, do not drop alias tables or roll back just source after using URL changes. Restore database only with an operator-reviewed recovery plan, as later writes may be lost.
