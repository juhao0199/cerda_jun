# V1.9.4.3 — Technical Site Audit & AI Crawler Management

Baseline: V1.9.4.2 (combined SEO/AEO/GEO release). No npm or Python dependency added. Public marketing UI and article content are unchanged. `/robots.txt` moves from the metadata route to an explicit HTTP handler backed by the database, with 503 on upstream failure.

## Upgrade

1. Finish, commit and merge V1.9.4.2; verify a clean worktree. Create `feature/v1.9.4.3-technical-audit` (skip if already on that branch). Back up PostgreSQL and verify the dump.
2. `git apply --check ~/Downloads/cedar-v1.9.4.3-technical-audit.patch && git apply ~/Downloads/cedar-v1.9.4.3-technical-audit.patch`.
3. `docker compose up -d --build backend`; then `docker compose exec backend python manage.py makemigrations --check --dry-run`, `docker compose exec backend python manage.py migrate`, and `docker compose exec backend python manage.py check`.
4. Restart frontend (`npm --prefix frontend run dev`). Use `/workspace/audit` and `/workspace/crawlers`. Check `curl -i http://localhost:3000/robots.txt`.
5. On Docker Desktop for Mac, the backend scans `http://host.docker.internal:3000` by default. The Next server must be running and reachable from the container; if needed launch `npm --prefix frontend run dev -- --hostname 0.0.0.0` on a trusted local network. To override, set `SITE_AUDIT_ORIGIN` in the root `.env`, then recreate backend. Only a deployment administrator should set this variable; it must be a trusted HTTP(S) origin with no path, userinfo or query. Set `SITE_ORIGIN` (Django) and `SITE_URL` (Next.js) to the same public origin. Use `npm --prefix frontend run build` followed by `npm --prefix frontend run start` instead of dev for more representative results (cold dev compilation can time out).
6. Production: apply migration and updated runtime grants via the existing `migrate` service, rebuild backend/frontend and reload Nginx with the changed allowlist. The configured audit target is the private `http://frontend:3000` service, not the public TLS edge. Do not expose that internal service. Origin scan cannot verify CDN, WAF, public DNS, TLS termination, real crawler access or public indexing. Verify those separately from an external network.

## Audit

Owner starts an anonymous server-side HTTP scan. Staff can read reports; Client and anonymous users cannot access reports or controls. A PostgreSQL advisory lock prevents simultaneous scans; existing rate limiter permits at most five runs per shared five-minute bucket. Each report stores measured status, duration, title/description/canonical, H1 count, image alt attribute presence, noindex signal, JSON-LD syntax diagnostics, sitemap checks, and supported internal link responses. No page HTML is retained. Redirect destinations have query/fragment stripped and are never followed. No browser JavaScript or external URL fetching. Scope: `/`, `/blog`, `/privacy`, and `/blog/<slug>`; includes published article inventory and same-origin sitemap URL set. No arbitrary path, private endpoint, query-link, image asset, fragment target or competitor scan. Up to 12 pages per batch, 8 extra discovered paths; next batch uses current inventory (not a frozen crawl session). Requests have short timeouts and 2 MiB body caps; budget exhaustion is reported as incomplete, not success. The 17-second scheduling budget is best-effort; slow networking may still exceed it. Report history shows the last 30 reports; earlier records remain in PostgreSQL. No automatic deletion or scheduling.

JSON-LD checks verify parseability/top-level type, not full schema.org validity or Google rich-result eligibility. Noindex signals are diagnostic, not actual indexing state. H1 count is editorial guidance. HTTP duration is server request time, not Core Web Vitals. Empty alt is allowed for decorative images. Broken links are limited to probed supported internal URLs returning HTTP 4xx/5xx. No search ranking or AI citation metric is invented.

## Crawler policy

The migration seeds all agents as `inherit` to avoid changing public crawling behavior; `/internal/` is additionally disallowed. Owner can explicitly allow public paths or disallow all per supported agent/token. Specific allow groups repeat private-path disallows, because explicit groups need their own rules. Staff is read-only; edits use version checks, CSRF and origin validation; writes are audited. Saving publishes robots.txt immediately, independently of Blog drafts. A comparison in Technical audit checks whether the observed origin output matches the saved policy at scan start. Policy is advisory, not authentication or WAF enforcement. ChatGPT-User and Perplexity-User are noted, not editable: user-triggered fetchers may ignore robots.txt. Google-Extended is a training/grounding token, not a Google Search ranking control. Do not block search crawlers unless intentionally opting out. No live bot log analysis or IP verification is included.

The E2E additions use mock API responses to verify interaction and access boundaries, not real crawler results. Test actual scan by opening the audit page with the frontend running and verify recorded findings/statuses against `curl`. Edit GPTBot without changing OAI-SearchBot, save, and inspect `/robots.txt`; restore the original policy afterward if testing. Keep the new DB migration when rolling back only application code; the old static robots route will no longer respect the saved policy. Back up and plan rollback before publishing policy changes.
