# V1.9.4.5 — Competitor & Content Gap Analysis

Base: V1.9.4.4 **AI Monitoring**, including the monitoring label hotfix. Do not use the cancelled Search Console branch. No new dependencies. No network requests to competitors or AI providers.

## Workflow
1. Open `/workspace/competitors`. Owner registers a company and hostname (root and `www` matched exactly). The identity is immutable; archive/restore preserves history.
2. Open its benchmark. Select a tracked prompt and one existing recorded measurement in the evidence selector. Record whether the competitor brand was actually present, absent, or inconclusive in that exact response and supply a short evidence excerpt. Source matches are derived only from the stored measurement URLs. One observation per competitor/measurement; no rewrites.
3. Compare matched samples. Filter by period, engine or selected prompt. Brand share is Cedar mentions divided by the sum of Cedar and that competitor's mentions, using only checks where both brand outcomes are determinate. Both present counts as two mentions; both absent adds no mentions. No denominator means unavailable. This is not all-market share. A source match is positive evidence of a *reported* URL, not independent verification; a missing URL is not evidence of absence. Citation gap signals require an explicitly absent Cedar citation and a matching recorded competitor source. Filters over 10,000 paired rows require narrowing; history is still paginated.
4. Create a content opportunity from a paired row, or select a prompt and create a hypothesis without an observation. An explicit competitor gap requires a paired record. Specify a private brief, target path (optional) and reviewer-selected priority. Change status (open/in progress/done/dismissed) using version checks. Opportunities are not published content.
5. Published content coverage checks a reviewer-entered literal phrase in visible title, summary and text of up to 200 published blog snapshots. Reports actual scanned and match counts, warns when partial, and returns up to 50 matches. It does not check static pages, synonyms, semantic coverage or draft text.
6. Create a linked private article draft by supplying title, slug, summary, category and actual initial body text. Internal brief/evidence is never copied automatically. A transaction creates the post and revision, links it to the opportunity, and marks the opportunity in progress. Existing slugs and aliases are reserved; repeated creation is blocked. Continue editing from Blog CMS. Owner alone can publish via existing workflow. Completing an opportunity is a manual editorial decision; publishing does not automatically prove the gap is closed.

## Roles and deployment
Owner manages competitor identity; Owner/Staff record observations and manage opportunities. Client/anonymous denied. Existing CSRF, exact origin, session, role locks, version checks and audit are reused. Evidence is append-only; no new public API. Apply migration `blog.0009_competitor_opportunities`. Production: update Nginx and run `infrastructure/postgres/runtime-grants.sql` as migrator following existing release procedure. Keep production DB private. No API key or new env variable needed.

## Upgrade and tests
Back up PostgreSQL; apply patch with `git apply --check` then `git apply`. Rebuild backend; `makemigrations --check --dry-run`, `migrate`, `check`. Restart frontend. Run the full existing Django test suite and frontend unit/typecheck/build; add `competitors.spec.ts` to the existing Playwright command. The new browser test mocks API responses; Django tests validate actual API/DB logic when run in local project.

Limitations: manually recorded AI results, pairwise not market-wide share, no automatic competitor discovery/crawling, no paid APIs, no semantic or site-wide static content audit, no auto publication. No monitoring data or competitors are seeded. No Search Console integration.
