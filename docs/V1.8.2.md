# V1.8.2 — sales pipeline upgrade

Apply from project root after V1.8.1. No database migration, npm package, or auth configuration change. Existing leads and clients remain unchanged. Back up the source first; use `git apply --check` before applying the patch. The patch does not touch next.config.ts, so any local Turbopack fix is preserved.

- Board: five stage columns, independently paginated (25 per page). Global stage counts are not filtered counts. Desktop drag/drop supports only existing server-approved transitions. Touch/keyboard use the drawer's explicit move buttons. Won conversion always requires confirmation. Native drag/drop, not a touch drag library.
- Table: same search and server-side filters. Date boundaries use UTC, end date inclusive. One saved browser view contains only mode, stage, service and date filters; never the search term, contact data or credentials. Cmd/Ctrl+K focuses search, not a full command palette.
- Drawer: native modal dialog with focus containment, project brief, stage actions and notes. Existing 50-event activity limit retained. Stage mutation projects the visible page optimistically, rolls back on error, then reloads authoritative state. No automatic retries of writes; a lost response can mean the server already committed. Server version/transaction/CSRF/role checks remain authoritative.
- Scope: existing Owner/Staff shared CRM, Client denied. No new endpoints; extended GET leads filters. No staff assignment, full custom saved-view library, arbitrary field editing or new auth behavior. No actual quote or billing action.

## Run

```sh
docker compose up -d --build backend
docker compose exec backend python manage.py check
docker compose exec backend python manage.py makemigrations --check --dry-run
docker compose exec backend python manage.py test apps.accounts apps.inquiries --verbosity=2
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

Stop existing dev server before E2E (config can reuse an existing server). From frontend: `npx playwright install chromium` then `npm run test:e2e -- pipeline.spec.ts`. Tests mock API for browser interaction; run Django tests separately for actual authorization. Restart dev server and visit `/workspace/leads`. If production container is deployed, use the production deployment procedure; don't expose dev servers publicly.
